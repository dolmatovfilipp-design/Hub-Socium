# Фаза 2 — точка стыковки с фазой 1

Модуль `src/voice/dictation` сам ведёт диктовку, запись голосового и подтверждение отправки. Каркас голоса (раздел «Управление интерфейсом», индикатор, навигация, серверное распознавание для iPhone) сюда не входит.

Кодового слова нет. Фраза целиком сравнивается с коротким именем команды.

## Что вызывает фаза 1

1. Пишет настройки в `localStorage` под ключом `hub-voice-prefs-v1` и в той же вкладке шлёт событие `hub-voice-prefs`. Чужой код этот ключ только читает.

```json
{
  "voiceEnabled": true,
  "preset": "chat",
  "silenceSeconds": 3,
  "speechRate": 1,
  "voiceReplies": true,
  "commands": { "C-12": true }
}
```

`preset`: `reading` (набор «Чтение и навигация»), `chat` («Переписка»), `publish` («Публикации»). Пауза тишины — целое от 1 до 8, по умолчанию 3. Переключатели команд фазы 2 можно взять из `PHASE2_CATALOG`, не копируя фразы вручную.

2. Ставит мост и забирает микрофон команд себе:

```ts
window.__HUB_VOICE_PHASE1__ = {
  ownsRecognition: true,
  speak: (text) => { /* синтез фазы 1 */ },
  setIndicator: (label) => { /* подпись индикатора */ },
}
window.dispatchEvent(new Event('hub-voice-phase1'))
```

Пока `ownsRecognition` не стоит, модуль сам открывает Web Speech API (`ru-RU`) как запасной путь. На записи голосового этот запасной путь молчит: микрофон занят `MediaRecorder`.

3. Каждую законченную фразу отдаёт так:

```ts
const result = window.__HUB_DICTATION__.submitPhrase(text)
if (result.consumed) return
```

`consumed: false` значит, что это не команда фазы 2 и не текст открытой диктовки. Навигацию («лента», «сообщения», «назад») фаза 2 не забирает.

Пока `getSnapshot().kind === 'recording'`, распознавание команд лучше поставить на паузу. Остановка — кнопка «Стоп», тишина или фраза «стоп», если она всё же дошла.

4. Комментарий с ленты, где дока нет:

```ts
import { planFeedComment, readVoicePrefs } from './voice/dictation'
const plan = planFeedComment(phrase, focusedPostId, readVoicePrefs())
if (plan.navigateTo) navigate(plan.navigateTo)
```

Повторно вызывать `submitPhrase('комментарий')` не нужно: экран ответа забирает флаг `sessionStorage` `hub-dictation-pending` и сам открывает диктовку.

Фокус сообщения в чате: `setDictationFocus(messageId)`. Без него берётся последнее сообщение.

## Поведение, которое уже внутри модуля

- «ответь» / «ответ» — диктовка в поле ответа. «готово» или «отправить» спрашивает «Отправить?». Уходит после «да» или «отправить». Молчание 8 секунд говорит «Отменила» и ничего не отправляет.
- «ответь на это» ставит ответ на сообщение в фокусе и ждёт диктовку.
- «комментарий» на экране ответа на пост — та же диктовка, вопрос «Опубликовать комментарий?».
- «редактировать последнее» / «исправь последнее» — диктовка и вопрос. Медиа не правится.
- «удали последнее» — только «да, подтверждаю». Обычное «да» не удаляет. В наборы не входит, пока в `commands` нет `"C-12": true`.
- «запиши голосовое» и кнопка микрофона поднимают блок: иконка микрофона, красная точка, таймер, уровень с `AnalyserNode`, подпись про паузу тишины. Через 3 секунды тишины (порог по первым 300 мс), по «стоп» или по кнопке запись переходит к «Отправить или перезаписать?». Короче 400 мс — «Слишком коротко». Дольше 2 минут в чате и 60 секунд у ответа на пост — тот же предпросмотр, без отправки.
- «отправить» и «да» на этом предпросмотре загружают файл и вызывают отправку. «перезаписать» стирает blob и пишет заново. «отмена» стирает blob и закрывает блок.
- Пока «Управление голосом» выключено, старая кнопка «Стоп» в чате по-прежнему отправляет голосовое сразу.

## Хранилище

`storeVoiceRecording` кладёт уже подтверждённое голосовое в текущий разбор медиа: `POST /v1/media/upload`. Сервер пишет объект в тот же S3-бакет (Selectel, если заданы `S3_*`) с префиксом `media/`. Префикс `voice-stt/` и срок в 24 часа — это запись команды фазы 1, её этот модуль не создаёт. До «отправить» файл остаётся в памяти вкладки.
