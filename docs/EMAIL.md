# Почта (SMTP) и сброс пароля

Сброс пароля отправляет 6-значный код на почту аккаунта. Отправка идёт по обычному SMTP, любым провайдером (Яндекс 360, Mail.ru для бизнеса, Unisender, SendGrid, Mailgun, Amazon SES, свой Postfix). Внешних Go-зависимостей нет, только стандартная библиотека.

## Как это работает

1. Пользователь вводит email, телефон или имя на экране «Сброс пароля».
2. API находит аккаунт и отправляет код **на email, сохранённый в аккаунте**, а не на то, что ввёл запрашивающий. Поэтому чужой код получить нельзя.
3. Пользователь вводит код и новый пароль. Код одноразовый и действует 15 минут.
4. После смены пароля все сессии завершаются, а на почту приходит уведомление «Пароль изменён».

Письма уходят из фоновой очереди (2 воркера, до 3 попыток с паузой 2 с и 10 с), поэтому время ответа API не зависит от того, существует ли аккаунт.

## Настройка

Переменные окружения API (`backend/.env` или `deploy/.env.prod`):

| Переменная | Обязательна | По умолчанию | Описание |
|------------|:-----------:|--------------|----------|
| `SMTP_HOST` | да | пусто = почта выключена | Имя хоста SMTP-сервера, без схемы и порта |
| `SMTP_FROM` | да | | Отправитель: `no-reply@example.com` или `Get Hub <no-reply@example.com>` |
| `SMTP_PORT` | нет | 587 (465 для `tls`, 25 для `none`) | Порт |
| `SMTP_TLS` | нет | `starttls`, а на порту 465 `tls` | `starttls`, `tls` (он же `ssl`) или `none` |
| `SMTP_USERNAME` | нет | | Логин; задаётся вместе с паролем |
| `SMTP_PASSWORD` | нет | | Пароль или API-ключ |

Примеры:

```bash
# Яндекс 360 / Яндекс Почта для домена (SSL)
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USERNAME=no-reply@example.com
SMTP_PASSWORD=<пароль приложения>
SMTP_FROM=Get Hub <no-reply@example.com>

# SendGrid (STARTTLS), логин всегда `apikey`
SMTP_HOST=smtp.sendgrid.net
SMTP_PORT=587
SMTP_USERNAME=apikey
SMTP_PASSWORD=<API key>
SMTP_FROM=Get Hub <no-reply@example.com>
```

Точные хосты и порты уточняйте в документации вашего провайдера. Адрес в `SMTP_FROM` почти всегда должен принадлежать домену, который вы подтвердили у провайдера.

### Режимы TLS

| `SMTP_TLS` | Что делает |
|------------|------------|
| `starttls` | Подключается без шифрования и **обязательно** переходит на TLS. Если сервер STARTTLS не предлагает, письмо не отправляется (тихого отката на открытый канал нет). |
| `tls` | TLS с первого байта (SMTPS, порт 465). |
| `none` | Без шифрования. Только для локального релея или тестового приёмника. Если задан логин и пароль, хост должен быть `localhost`/`127.0.0.1`: пароль в открытом виде на внешний сервер API не отправит. |

Сертификат сервера проверяется всегда (TLS 1.2 и выше).

### Что происходит без SMTP

| Режим | `SMTP_HOST` пуст |
|-------|------------------|
| Production | `POST /v1/auth/password-reset/request` отвечает `503 email_unavailable`, в логе при старте предупреждение. Код не создаётся и никуда не отдаётся. |
| Dev (`HUB_ENV=dev`, embedded PG) | Код возвращается в ответе API (`dev_code`), письмо не отправляется. Если SMTP настроен, `dev_code` не возвращается и в dev. `HUB_HIDE_RESET_CODE=1` отключает `dev_code` совсем. |

Неверная конфигурация (например, `SMTP_HOST` без `SMTP_FROM` или логин без пароля) останавливает запуск API с понятным сообщением.

## Проверка

```bash
cd backend && go build -o bin/api ./cmd/api

# Отправить тестовое письмо тем же SMTP_* и выйти (код возврата 0 при успехе)
./bin/api -send-test-email you@example.com
```

При запуске API подключается к SMTP, проходит TLS и авторизацию без отправки письма и пишет в лог `smtp check ok` или `smtp check failed` с причиной. Проверьте это сообщение после деплоя.

### Локальная разработка с Mailpit

[Mailpit](https://mailpit.axllent.org) принимает любые письма и показывает их в браузере. Ничего наружу не уходит.

```bash
cd backend
docker compose up -d mailpit         # SMTP :1025, веб-интерфейс http://localhost:8025
```

```bash
# backend/.env
SMTP_HOST=127.0.0.1
SMTP_PORT=1025
SMTP_TLS=none
SMTP_FROM=Get Hub <no-reply@hub.local>
```

Запустите `make run-embedded` и фронт в API-режиме, запросите сброс пароля и откройте письмо в Mailpit. Для демо-пользователя `филипп` почта `philip@hub.app`.

## Доставляемость

Чтобы письма не попадали в спам:

- Отправляйте с домена, которым владеете, и настройте у DNS-провайдера **SPF**, **DKIM** (ключ даёт SMTP-провайдер) и **DMARC** для этого домена.
- Используйте отдельный адрес вида `no-reply@…`, не личный ящик.
- Не меняйте тему письма на рекламную: письма транзакционные.

## Безопасность и лимиты

- Код хранится как HMAC от (секрет сервера, id пользователя, код): утечка таблицы не позволяет подобрать коды офлайн.
- 5 неверных попыток, и код сгорает. Счётчик атомарный, параллельные запросы лимит не обходят.
- На аккаунт: не чаще одного кода в минуту и не более 5 в час. При превышении API отвечает как обычно (`200`), но письмо не отправляет, чтобы нельзя было узнать, есть ли такой аккаунт.
- На IP: 20 запросов кода и 40 подтверждений за 10 минут (`429` с `Retry-After`).
- Ответы одинаковы для несуществующего аккаунта, аккаунта без email и аккаунта в лимите.
- Код не попадает в тему письма и в логи. В логах адрес маскируется (`a***@example.com`).
- Известный компромисс: тот, кто знает имя аккаунта, может сжигать его актуальный код неверными попытками. Сменить пароль это не позволяет, но мешает сбросу, пока идёт атака. Лимиты по IP ограничивают такую атаку, а владельцу достаточно запросить новый код через минуту.
- Код привязан к ключу, производному от `JWT_SECRET`: при смене `JWT_SECRET` ещё не использованные коды перестают действовать.

Подробнее о лимитах: [`RATE-LIMITS.md`](./RATE-LIMITS.md).

## Ограничения

- Письмо получает только аккаунт с email. При регистрации по телефону почты нет: пользователь должен добавить её в профиле, пока помнит пароль. Сброс по SMS не реализован.
- Адрес при регистрации пока **не подтверждается** письмом (в форме регистрации демо-код `000000`). Подтверждение адреса стоит сделать следующим шагом на этой же инфраструктуре.
- Письма только на английские (ASCII) адреса; адреса с кириллицей в имени ящика не поддерживаются.

## Если письмо не пришло

| Симптом в логе API | Причина |
|--------------------|---------|
| `smtp check failed … auth` | Неверный логин или пароль, нужен пароль приложения |
| `smtp check failed … STARTTLS` | Порт 465 с `SMTP_TLS=starttls`: поставьте `SMTP_TLS=tls` |
| `smtp check failed … certificate` | Хост в `SMTP_HOST` не совпадает с сертификатом |
| `mail delivery failed … 550` / `553` | Провайдер не принимает `SMTP_FROM`: подтвердите домен или ящик |
| `password reset throttled` | Сработал лимит на аккаунт (минута / 5 в час) |
| `mail sent`, но письма нет | Смотрите «Спам» и настройки SPF/DKIM/DMARC |
